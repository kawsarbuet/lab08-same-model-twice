# Framework comparison for Lakeshore Bike Share

**Status:** Draft evidence review. Run `python compare.py` with the required **TensorFlow** backend, and replace the marked placeholders with measured values before submitting. Do not treat the local Keras/Torch-backend preview as an official comparison.

The team needs a repeatable weekly bike-demand forecasting job maintained by two developers: one familiar with Keras and one with PyTorch. I implemented the Lab 07 network in both frameworks using two 64-unit ReLU hidden layers and one linear output. Both versions use the exact float32 arrays generated by `prepare.py`, MSE loss, Adam at learning rate 0.003, batch size 128, and 100 training epochs. Before training, the PyTorch weights are copied into Keras with a kernel transpose. The prediction-equivalence check uses the validation rows and a tolerance of 1e-5.

**Difference 1 — training code.** PyTorch's `train.py` explicitly loops over batches with `zero_grad`, `backward`, and `step`. Keras replaces that manual optimization loop with `compile` and `fit`; `train_keras.py` also uses `EarlyStopping(restore_best_weights=True)` and `ModelCheckpoint`. The shorter orchestration helps a small team maintain a weekly job, while PyTorch provides more explicit batch-level control.

**Difference 2 — model storage and inspection.** Keras saves a `.keras` checkpoint and exposes per-epoch `history.history` directly; Lab 07 retains the best PyTorch `state_dict` in memory and exports CSV learning histories. Both have useful debugging tools but expose their mechanics differently.

**Recommendation:** I would tentatively choose **PyTorch** for this two-person team if the planned Hugging Face experiments will rely on native PyTorch pretrained models. Its flexible training loop and direct compatibility would reduce future migration effort. This sacrifices Keras's concise `fit` and built-in callbacks. I would change the choice to **Keras** if the measured results are comparable and the weekly task remains a fixed tabular regression model without strong pretrained-PyTorch dependencies.
